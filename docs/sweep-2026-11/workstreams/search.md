*Batch 6C · bugfix · medium · `bugfix` · effort S.* Build the palette's collections from getEnabledViews, omitting notes, reviews and sprints when disabled, and ignore results whose view is not enabled to avoid stale selections.

### <a id="part-34"></a>PART-34 — The command palette returns items from disabled views
*medium · `bugfix` · effort S.* **Where:** `src/components/views/TodoApp.tsx:2274`; `src/components/views/TodoApp.tsx:868`; `src/components/views/TodoApp.tsx:256`; `src/components/views/TodoApp.tsx:1304`; `src/components/views/TodoApp.tsx:1480`; `src/components/views/TodoApp.tsx:1728`; `src/utils/globalSearch.ts:35`. **Problem.** CommandPalette receives every collection whatever the feature flags say. handleSearchResult switches to result.view, and the redirect then sends a disabled view back to List. Reviews search title, summary, entries and projects. Sprints also match the status label. The empty-query check differs (trimmed in one place, compared with an empty string elsewhere). Kanban's search box records no search history. **Proposal.** The owner decides which fields each entity's search covers (recommended: text, rich-text body, tags, references and comments), or Help is corrected instead. Adding search history to Kanban is a feature extension. **Done when.** Per-entity model tests cover the agreed fields, and a check confirms the Help text lists exactly those fields.

### <a id="struct-74"></a>STRUCT-74 — matchesSearch treats a blank query differently in BaseEntityModel than in the other models (not visible to users)
*low · `none` · effort S.* **Where:** `src/models/BaseEntityModel.ts:265`; `src/models/TodoModel.ts:1177`; `src/models/NoteModel.ts:445`; `src/models/ReviewModel.ts:456`; `src/models/SprintModel.ts:422`; `src/utils/globalSearch.ts:79-80`; `src/components/views/EntityListView.tsx:84`. **Problem.** BaseEntityModel returns early when searchText.trim() is empty, while Todo, Note, Review and Sprint return early only when searchText is exactly ''. Users cannot see the difference: globalSearch returns before matching when the trimmed query is blank (79-80), and EntityListView only calls matchesSearch when search.trim() is not empty (84). The trim branch is therefore unreachable, and the inconsistency exists only in the model API. **Proposal.** Align BaseEntityModel with the others (searchText === ''), or share one isBlankQuery helper that all five models use the same way. Switching every model to trim() instead would change filtering in List, Kanban and Notes for whitespace-only text, which needs an owner decision. **Done when.** Model tests with a query of ' ' pin identical behaviour across all five models; the existing search tests stay green.
